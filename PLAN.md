# План: свадебные приглашения

## Паттерн референсов (оба — Tilda, длинный скролл-лендинг)

**Страница приглашения** (`piwedding2.ru/sergetolesya/031026`):
1. Hero — имена пары, дата, фото, «листать вниз»
2. Приветственный текст
3. Место проведения
4. Программа дня (тайминг: сбор → церемония → банкет)
5. Дресс-код + палитра оттенков
6. Пожелания (конверты, «вино вместо цветов», без «Горько»)
7. Трансфер / логистика
8. Карта (embed Яндекс.Карт)
9. Telegram-чат праздника
10. RSVP-анкета (подтверждение до дедлайна)
11. Контакты организатора
12. Фоновая музыка (автоплей по кнопке)

**Каталог** (`dariwithlove.ru/catalog`): сетка карточек шаблонов, фильтры по категориям (свадьба / ДР / другое), «Смотреть демо» + «Заказать», SEO-текст.

## Стек

- **Astro + TypeScript** — подтверждаю, идеальный выбор: статика → мгновенная загрузка, zero-JS по умолчанию, интерактив — островками.
- CSS: vanilla CSS с custom properties (переменные = мгновенная смена темы/палитры шаблона, ноль зависимостей). Tailwind не нужен, пока секций мало.
- `astro:assets` для оптимизации фото (WebP, размеры) — критично для мобильных.
- Шрифты: self-host или Google Fonts с `font-display: swap`, max 2 семейства (Playfair Display + Montserrat — как в референсе).

## Этапы

### MVP (этап 1) — один шаблон приглашения
- `src/pages/[slug].astro` — страница приглашения.
- Данные приглашения — YAML/JSON content collection (имена, дата, место, тайминг, дресс-код, контакты). Никакого хардкода в разметке — это фундамент для будущих шаблонов.
- Компоненты-секции из списка выше, каждая — отдельный `.astro`, mobile-first (320px → вверх).
- RSVP-форма без бэка: отправка в Telegram через Bot API (fetch на `api.telegram.org` с токеном) — лениво и работает.
- Карта: iframe Яндекс.Карт с `loading="lazy"`.
- Музыка: `<audio>` + кнопка (автоплей браузеры всё равно блокируют).
- Плавные fade-up при скролле: IntersectionObserver, ~10 строк JS, без GSAP на MVP.

### Этап 2 — каталог
- `/catalog` — статичная сетка из content collection шаблонов, фильтры на чистом CSS/JS.
- Демо каждого шаблона = та же страница приглашения с демо-данными.

### Этап 3 — бэк (после MVP)
- Astro `output: 'server'` + Node adapter, БД (SQLite → Postgres).
- Админка: пары заполняют данные → генерится приглашение по slug.
- RSVP в БД вместо Telegram, статистика ответов.

## Принципы
- Mobile-first: верстка от 320px, desktop — max-width колонкой, десктопному виду референсы уделяют мало внимания, гости открывают с телефона.
- Скорость: цель LCP < 1.5с на 3G — никаких JS-фреймворков на клиенте, только прогрессивные островки.
- Каждая секция опциональна: шаблон рендерит только то, что есть в данных.
